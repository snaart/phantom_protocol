Telemetry (OpenTelemetry push)
---------------------------------------------------------------------------

The Phantom Protocol server opens no inbound metrics port — there is no /metrics
endpoint to scrape. Built with the telemetry-otel feature, it PUSHES metrics
and traces over OTLP/gRPC to an OpenTelemetry Collector:

  phantom-server --OTLP/gRPC push--> OTel Collector --> Prometheus / Tempo / SaaS

Point the server at your Collector via the chart's `telemetry` values — the
Deployment renders them into the container's OTEL_* env. An empty otlpEndpoint
leaves the exporter uninstalled (telemetry off). E.g.:

  --set 'telemetry.otlpEndpoint=http://otel-collector.{{ .Release.Namespace }}.svc.cluster.local:4317'

Other knobs (telemetry values → env): telemetry.serviceName (OTEL_SERVICE_NAME),
telemetry.tracesSamplerArg (OTEL_TRACES_SAMPLER_ARG, head-sampling ratio), and
telemetry.otlpHeaders (OTEL_EXPORTER_OTLP_HEADERS, auth headers for SaaS backends).

To land metrics in Prometheus, run a Collector with an otlp receiver plus a
prometheus exporter (or remote_write), and have Prometheus scrape the
COLLECTOR — never the phantom pods. To verify the server is pushing, watch the
Collector's own debug/logging exporter or query Prometheus for, e.g.:

  phantom_session_active{leg="tcp"}
